> 규칙을 손으로 짜던 기계에서, 데이터로 스스로 배우는 기계까지.
> 회귀 → 분류 → 파인튜닝을 직접 따라가며 이해한 학습 노트.

---

## 🗺️ 한눈에 보는 전체 지도

```
1강. 학습 = 예측 → 오차 → 조정 (반복)
2강. 데이터는 전부 숫자(벡터·텐서)로 바뀐다
3강. 회귀 — 카페 매출 (연속된 값 예측)
4강. 분류 — softmax로 확률 매겨 고르기
5강. 파인튜닝 — 남이 배운 것을 물려받기 (freeze)
6강. 규모 — 파라미터 폭발 → 왜 GPU가 필요한가
7강. 결론 — 【 데이터가 결과를 가른다 】
```

**딱 3가지만 기억하면 됩니다:**
1. **학습 = 예측 → 오차 → 조정의 반복** (마법이 아니라 숫자를 조금씩 미는 계산)
2. **뭐든 숫자로 바뀐다** (글 = 토큰·임베딩, 그림 = 텐서)
3. **모델 구조보다 데이터가 결과를 가른다**

## 1강. 규칙을 짜는 기계 → 배우는 기계

### 인공지능은 겹겹이 포개진 원

```
[ 인공지능 (AI) ]          ← 가장 넓은 개념
  [ 머신러닝 ]             ← 데이터로 스스로 배움
    [ 딥러닝 ]             ← 여러 층 신경망
      [ 생성형 AI ]        ← 챗봇 · 이미지 생성
```

### 왜 규칙을 직접 짜지 않을까?

개/고양이 구분, 손글씨 '7', 스팸 메일… **규칙을 손으로 쓰면 예외가 예외를 낳아 끝이 없습니다.**
- "귀가 뾰족하면 고양이" → 폴드귀 고양이가 반례
- "무료·당첨 차단" → "무 료", "당.첨"으로 비틀어 빠져나감

그래서 발상을 **뒤집습니다.** 규칙 대신 **예시(데이터)를 잔뜩 주고 기계가 규칙을 스스로 찾게** 하는 것 — 이것이 **학습(learning)** 입니다.
> 아서 새뮤얼(1959): "명시적으로 프로그래밍하지 않고도 컴퓨터가 배우게 하는 연구 분야"

### "배운다"의 뿌리를 만든 세 사람

| 인물 | 연도 | 기여 |
|------|------|------|
| **섀넌** | 1951 | 다음 글자 맞히기 게임 → 언어는 통계적으로 예측 가능. 오늘날 LLM의 **"다음 토큰 예측"** 이 이것 |
| **로젠블랫** | 1958 | 퍼셉트론 → **틀리면 가중치를 살짝 고친다**. 단, 한 겹이라 복잡한 패턴은 못 배움 |
| **러멜하트·힌턴·윌리엄스** | 1986 | **역전파** → 여러 층에게 "네가 오차에 얼마나 기여했나"를 뒤에서 앞으로 알려줘 고치게 함 |

### 학습의 핵심 고리

```
데이터 예시 → 예측 → 오차(틀린 정도) 계산 → 가중치 조정 → (반복)
```

- 예: 5를 예측했는데 정답이 7 → 오차 +2 → 조금씩 5.3, 5.6… 정답에 다가감
- 오차를 "언덕"으로 보고 가장 낮은 골짜기로 한 걸음씩 내려감 = **경사하강(gradient descent)**

### 꼭 기억할 두 가지
1. 학습 결과물은 규칙집이 아니라 **파라미터에 압축된 패턴** → 그래서 모델은 **자신 있게 틀릴 수 있음**
2. 정답이 달린 예시로 배우는 방식 = **지도학습(supervised learning)**

## 2강. 데이터를 숫자로 바꾸기

### 대전제: 기계는 오직 **숫자**만 다룬다

글도 그림도 → 무조건 **숫자로 변환** 먼저!

- **글:** 문장 → **토큰**(의미 있는 조각)으로 자르기 → 각 토큰을 **벡터**(숫자 묶음)로 변환 → 뜻을 담은 벡터 = **임베딩(embedding)**
- **그림:** 픽셀(밝기·색 숫자)의 격자. 손글씨 한 장(MNIST) = 28 × 28 = **784개 숫자**

### 텐서 사다리 — 차원이 하나씩 올라간다

```
스칼라 (0차)   숫자 1개          예: 매출 7
벡터   (1차)   숫자 한 줄         예: [방문객, 요일, 날씨]
행렬   (2차)   숫자 격자          예: 흑백 이미지
텐서   (3차+)  격자를 쌓음        예: 컬러사진 (R/G/B 3장)
```

### 벡터의 "비슷함"을 재는 두 가지
- **거리:** 두 점이 얼마나 가까운가 (서울–인천은 가깝고, 서울–부산은 멀다)
- **방향(각도):** 크기가 달라도 같은 쪽을 가리키면 "결이 같다"
- 핵심: **절대 위치가 아니라 점들 사이의 관계가 뜻을 만든다.**

### 신경망 한 층에서 벌어지는 일 — 세 박자

```
① 곱하고 (W, 가중치)   ② 더하고 (b, 편향)   ③ 비틀기 (활성화 함수)
```

- 식으로는 `Wx + b` → 여기에 활성화 함수
- **활성화 함수가 왜 필요?** 곱셈·덧셈만 쌓으면 층을 아무리 쌓아도 결국 직선 하나로 뭉개짐 → 구불구불한 실제 패턴을 못 그림
- **ReLU:** 음수는 0으로, 양수는 그대로 통과 → 이 작은 꺾임이 곡선을 그릴 수 있게 함

## 3강. 가장 작은 학습을 코드로 보기

### 목적
1·2강에서 배운 **"예측 → 오차 → 조정"** 이 진짜로 일어나는 걸 **가장 작은 모델**로 눈으로 확인.
파라미터가 딱 **2개**(weight 1개, bias 1개)뿐인 모델에게 데이터만 주고 규칙을 찾게 한다.

### 상황: 카페 매출 예측
- 가진 것: 지난 **30일치 (방문객 수, 매출)** 기록뿐
- 숨은 진짜 규칙: **매출 = 2 × 방문객 + 1** (매일 잡음 섞임)
- **모델은 이 '2'와 '1'을 모른다!** → 데이터만 보고 찾아내야 함

### 도구: PyTorch — 두 개념만
| 개념 | 하는 일 |
|------|---------|
| **텐서(tensor)** | 숫자 배열. CPU/GPU 어디서든 같은 코드로 돌아감 |
| **autograd(자동미분)** | `loss.backward()` 한 줄로 "각 파라미터가 오차에 얼마나 기여했나(=기울기)"를 자동 계산 → **역전파 대행** |

### 학습 코드 핵심 흐름

```python
w = 0, b = 0            # 엉뚱한 값(0)에서 출발
lr = 0.03               # 학습률 = 한 걸음의 크기

600번 반복:
    pred = w*방문객 + b               # ① 예측
    loss = ((pred - y)**2).mean()      # ② 오차 (평균제곱오차 MSE)
    loss.backward()                    # ③ 기울기 계산 (autograd)
    w -= lr * w.grad                   # ④ 기울기 반대쪽으로 한 걸음 (경사하강)
    b -= lr * b.grad
```

### 결과
- 학습 후: **매출 = 2.07 × 방문객 + 0.79** ← 숨은 정답 (2, 1)과 거의 일치! 🎯
- 왼쪽 그래프: 빨간 직선이 점들 한가운데를 지나감
- 오른쪽 그래프: 오차(loss)가 급히 떨어졌다가 평평해짐
- **기울기 2.07** = "방문객 100명 늘면 매출 약 207만원 증가" (변화율)
- **절편 0.79** = 방문객 0명인 날에도 잡히는 기본 매출 (배달·포장 등)

### 그래서 LLM도?
**똑같다.** 다른 건 오직 **규모**뿐:
- 파라미터 2개 → **수십억~수천억 개**
- 예측 대상: 숫자 하나 → **다음 토큰의 확률분포**
- 이 작은 학습을 웹 전체 규모로 돌린 것 = **사전학습(pretraining)**

## 4강. softmax와 MNIST로 분류하기

### 회귀 vs 분류
| | **회귀 (3강)** | **분류 (4강)** |
|---|---|---|
| 맞히는 것 | 연속된 **숫자** | 어느 **종류**인가 |
| 예시 | 카페 매출 (207만원) | 손글씨 0~9, 스팸, 개/고양이 |
| 출력 | 값 하나 | **후보마다 매긴 확률** |

### 분류의 출력 = 확률
```
"3일 확률 88%, 8일 확률 9%, 5일 확률 2%..."
```
- 가장 높은 확률의 후보를 답으로 고름
- **확률값 자체가 "얼마나 확신하는지"** 를 알려줌 (0.66이면 애매, 0.99면 강한 확신)

### ⭐ softmax = 점수를 확률로 바꾸는 장치
raw 점수(**로짓, logit**)를 → **모두 0~1 사이이고 합이 1인 확률**로 변환

**계산 두 단계** (예: 로짓 `[2.0, 1.0, 0.1]`):
```
① exp 적용:          [7.39, 2.72, 1.11]   ← 모두 양수로, 차이를 벌림
② 합(11.2)으로 나눔:  [0.66, 0.24, 0.10]   ← 합 = 1 (확률 완성!)
```

**왜 이름이 softmax?**
- 그냥 max: 가장 큰 하나만 1, 나머지 0 → 딱 잘라버림(hard)
- softmax: 큰 값에 큰 확률 주되 나머지에도 조금씩 남김 → 부드럽게(soft) → **soft + max**

### 챗봇(LLM)과 똑같다!
softmax는 언어모델이 **"다음에 올 단어"** 를 고를 때 쓰는 것과 **똑같은 장치**.
- 숫자 분류기: 후보 **10개**(0~9)에 확률
- 언어모델: 후보 **수만 개**(토큰)에 확률
- **개수만 다르고 원리는 완전히 동일**

### 오늘의 핵심 실험 (MNIST)
- 전체 데이터 학습 → 정확도 **약 96%대**
- 데이터를 **10%로 줄이면** → 정확도 **떨어짐**
- ❗ 이유: 모델이 나빠서가 아니라 **볼 예시(데이터)가 줄었기 때문**
- → **"데이터가 결과를 가른다"**

## 5강. 남이 배운 것을 물려받는 파인튜닝

### 왜 필요한가?
- MNIST는 밑바닥부터 배워도 금방 (간단하니까)
- 그런데 **개/고양이 구분**은 "귀·털·눈·질감" 같은 복잡한 시각 특징이 필요
  → 밑바닥부터 배우려면 **엄청난 사진 + 엄청난 계산** 필요
  → 근데 우리에겐 **사진 몇백 장뿐**일 수도 있음

### 해결: 남이 배운 걸 물려받자
- 이미 **수백만 장**으로 학습된 모델(예: **ResNet18** — 18은 층 개수)은
  이미 **"선·모서리·질감·형태를 보는 눈"** 을 갖고 있음
- 이 눈은 **그대로 두고**, **마지막 판단 부분만** 내 문제(개/고양이)에 맞게 조금 더 학습
- 이것이 **파인튜닝(fine-tuning)**, 넓게는 **전이학습(transfer learning)**

### 무엇이 전이되나? — 층의 역할 차이

```
입력 이미지
  ↓
[앞쪽 층]  선·모서리·색     ← 보편적! (무엇이든 이미지면 쓸모) → 물려받음 (freeze)
  ↓
[중간 층]  질감·무늬
  ↓
[뒤쪽 층]  눈·귀·형태       ← 구체적 → 새로 배움
  ↓
[판단]    개 / 고양이
```

- **freeze(얼린다):** 그 층의 가중치를 **학습 중에 바꾸지 않고 고정** → 계산·데이터 절약
- **적은 데이터로도 잘 되는 이유** = 사전학습된 특징을 **재사용**하니까

### 실험 관찰 포인트
- **데이터가 적을 때 → 사전학습 쪽이 크게 앞선다** (핵심!)
- 학습 시간은 카페·MNIST보다 훨씬 길어짐 → 왜인지는 6강에서

## 6강. 왜 내 노트북으론 벅찰까

### 원인: 파라미터 개수가 문제마다 하늘과 땅 차이
| 학습 | 파라미터 규모 | 어디서 도나 |
|---|---|---|
| 카페 선형모델 | **2개** (w, b) | 노트북에서 즉시 |
| MNIST 분류기 | 수만~수십만 | 노트북 CPU로 몇 분 |
| ResNet18 파인튜닝 | 약 **1,100만** | GPU 권장 (Colab) |
| 대형 언어모델(LLM) | **수십억~수천억** | GPU 수백~수천 대, 데이터센터 |

- 학습은 매 스텝마다 "예측 → 오차 → 조정" → 그 계산의 대부분이 **방대한 행렬 곱셈**
- 파라미터·데이터가 늘수록 곱셈 횟수가 **폭발적으로** 증가

### CPU vs GPU
```
CPU:  큰 코어 몇 개     → 복잡한 일을 순서대로 빠르게
GPU:  작은 코어 수천 개  → 단순한 계산을 한꺼번에 (병렬)
```
- 학습은 "같은 계산을 엄청나게 많이 병렬로" 하는 일 → **GPU에 딱 맞음** (CPU보다 수십~수백 배 빠름)
- 행렬 곱셈이 병렬에 잘 맞는 이유: 그 안의 곱셈들이 **서로 독립적**이라 순서 없이 한꺼번에 가능

### 규모 감각
- LLM의 수천억 파라미터를 **1초에 하나씩 세도 수천 년** 😲
- LLM을 처음부터 학습하려면 **GPU 수천 대 × 수 주 = 수백만~수억 달러**

### 그래서 실무의 현실
- 대부분 **직접 훈련하지 않음** → 이미 학습된 모델을 **파인튜닝**하거나 **API로 호출**
- 참고: **Colab / Colab CLI**(`google-colab-cli`)로 GPU를 빌려 쓸 수 있고,
  AI 코딩 에이전트가 이 명령을 대신 실행할 수도 있음

## 7강. 결국 데이터가 전부다

### 오늘 "배운다"를 세 번 직접 봤다
| 실습 | 무엇을 | 어떻게 |
|---|---|---|
| **회귀** (카페 매출) | 연속된 숫자 예측 | 예측→오차→조정으로 직선 규칙 찾기 |
| **분류** (MNIST) | 어느 범주인지 | softmax로 후보마다 확률 매겨 고르기 |
| **파인튜닝** (개/고양이) | 내 문제에 맞춤 | 남의 사전학습 특징 물려받아 적은 데이터로 |

### ⭐ 셋을 관통하는 한 문장
> **모델 구조보다 데이터가 결과를 가른다.**

- 데이터 10%로 줄이면 → 정확도 떨어짐
- 사전학습 특징 물려받으면 → 적은 데이터로도 잘 됨
- 그래서 **AI 다루는 사람의 진짜 일 = "좋은 모델 고르기"가 아니라 "좋은 데이터를 모으고 검증하기"**

### 핵심 질문과 답
| 핵심 질문 | 오늘의 답 |
|---|---|
| AI가 "배운다"는 건? | 규칙을 손으로 짜는 대신, 데이터에서 예측→오차→조정을 반복해 패턴을 찾는 것 |
| 회귀 vs 분류? | 회귀는 연속된 값을, 분류는 어느 범주인지(softmax 확률)를 예측 |
| softmax는? | 여러 후보 점수를 합이 1인 확률로 바꿔, 확신 정도와 함께 하나를 고르게 함 |
| 파인튜닝은 왜? | 사전학습 특징을 물려받아 적은 데이터·계산으로 내 문제에 맞추려고 |
| 왜 GPU? | 학습은 방대한 행렬 곱셈이고, GPU는 이를 대규모 병렬로 처리 |
| AI 활용가의 진짜 일? | 모델 고르기보다, 좋은 데이터를 모으고 결과를 의심·검증하기 |
