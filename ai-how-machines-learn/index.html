복습 노트 · 전 7강

AI는 어떻게
배우나

규칙을 손으로 짜던 기계에서, 데이터로 스스로 배우는 기계까지. 회귀 → 분류 → 파인튜닝을 직접 따라가며 이해한 학습 노트.

🗺️ 한눈에 보는 전체 지도

1학습 = 예측 → 오차 → 조정 (반복)
2데이터는 전부 숫자(벡터·텐서)로 바뀐다
3회귀 — 카페 매출 (연속된 값 예측)
4분류 — softmax로 확률 매겨 고르기
5파인튜닝 — 남이 배운 것을 물려받기
6규모 — 파라미터 폭발 → 왜 GPU인가
7결론 — 데이터가 결과를 가른다

⭐ 딱 3가지만 기억하면 됩니다

  1. 학습 = 예측 → 오차 → 조정의 반복 (마법이 아니라 숫자를 조금씩 미는 계산)
  2. 뭐든 숫자로 바뀐다 (글 = 토큰·임베딩, 그림 = 텐서)
  3. 모델 구조보다 데이터가 결과를 가른다
1

규칙을 짜는 기계 → 배우는 기계

왜 규칙을 직접 짜지 않을까?

개/고양이 구분, 손글씨 '7', 스팸 메일… 규칙을 손으로 쓰면 예외가 예외를 낳아 끝이 없어요.

  • "귀가 뾰족하면 고양이" → 폴드귀 고양이가 반례
  • "무료·당첨 차단" → "무 료", "당.첨"으로 비틀어 빠져나감

그래서 발상을 뒤집어요. 규칙 대신 예시(데이터)를 잔뜩 주고 기계가 규칙을 스스로 찾게 하는 것 — 이것이 학습(learning).

학습의 핵심 고리

데이터 예시 → 예측 → 오차(틀린 정도) → 가중치 조정 → (반복)

오차를 "언덕"으로 보고 가장 낮은 골짜기로 한 걸음씩 내려감 = 경사하강(gradient descent)

💡 학습 결과물은 규칙집이 아니라 파라미터에 압축된 패턴 → 그래서 모델은 자신 있게 틀릴 수 있어요. 정답 달린 예시로 배우는 방식 = 지도학습.
2

데이터를 숫자로 바꾸기

대전제: 기계는 오직 숫자만 다룬다

  • 글 → 토큰(의미 조각)으로 자르기 → 벡터로 변환 → 뜻을 담은 벡터 = 임베딩
  • 그림 → 픽셀 격자. 손글씨 한 장(MNIST) = 28×28 = 784개 숫자

텐서 사다리 — 차원이 하나씩 올라간다

스칼라 (0차)   숫자 1개       예: 매출 7
벡터   (1차)   숫자 한 줄     예: [방문객, 요일, 날씨]
행렬   (2차)   숫자 격자      예: 흑백 이미지
텐서   (3차+)  격자를 쌓음     예: 컬러사진 (R/G/B 3장)

신경망 한 층의 세 박자

① 곱하고 (W)   ② 더하고 (b)   ③ 비틀기 (활성화 함수)

활성화 함수가 왜? 곱셈·덧셈만 쌓으면 층을 아무리 쌓아도 직선 하나로 뭉개짐. ReLU(음수는 0, 양수는 통과)의 작은 꺾임이 곡선을 그릴 수 있게 해줘요.

핵심: 절대 위치가 아니라 점들 사이의 관계(거리·방향)가 뜻을 만든다.
3

가장 작은 학습을 코드로 보기

카페 매출 예측 — 파라미터 딱 2개

가진 것: 지난 30일치 (방문객, 매출) 기록뿐. 숨은 진짜 규칙은 매출 = 2 × 방문객 + 1 (잡음 섞임). 모델은 이 '2'와 '1'을 모르고, 데이터만 보고 찾아야 해요.

w=0, b=0           # 엉뚱한 값에서 출발
lr=0.03            # 학습률 = 한 걸음 크기
600번 반복:
    pred = w*방문객 + b            # ① 예측
    loss = ((pred-y)**2).mean()    # ② 오차 (MSE)
    loss.backward()                # ③ 기울기 계산 (autograd)
    w -= lr*w.grad; b -= lr*b.grad # ④ 경사하강 한 걸음

결과: 매출 = 2.07 × 방문객 + 0.79 ← 숨은 정답 (2, 1)과 거의 일치! 🎯

LLM도 똑같아요. 다른 건 오직 규모뿐 — 파라미터 2개 → 수천억 개, 예측 대상: 숫자 하나 → 다음 토큰의 확률분포. 이 작은 학습을 웹 전체로 돌린 것 = 사전학습.
4

softmax와 MNIST로 분류하기

회귀 vs 분류

회귀 (3강)분류 (4강)
맞히는 것연속된 숫자어느 종류인가
예시카페 매출 (207만원)손글씨 0~9, 스팸
출력값 하나후보마다 매긴 확률

⭐ softmax = 점수(로짓)를 확률로 바꾸는 장치

로짓 [2.0, 1.0, 0.1]
① exp:        [7.39, 2.72, 1.11]  ← 양수로, 차이 벌림
② 합으로 나눔: [0.66, 0.24, 0.10]  ← 합=1 (확률 완성!)

왜 softmax? 그냥 max는 하나만 1·나머지 0(hard). softmax는 큰 값에 큰 확률 주되 나머지에도 조금 남김(soft) → soft + max.

챗봇과 똑같아요! 숫자 분류기는 후보 10개, 언어모델은 후보 수만 개(토큰)에 확률. 개수만 다르고 원리는 완전 동일. 그리고 MNIST 데이터를 10%로 줄이면 정확도가 떨어져요 → "데이터가 결과를 가른다".
5

남이 배운 것을 물려받는 파인튜닝

왜 필요한가?

개/고양이 구분은 복잡한 시각 특징이 필요해서 밑바닥부터 배우려면 엄청난 사진+계산이 필요해요. 근데 우리에겐 사진 몇백 장뿐일 수 있죠.

해결: 이미 수백만 장으로 학습된 모델(예: ResNet18)은 "선·모서리·질감·형태를 보는 눈"을 이미 가졌어요. 이 눈은 그대로 두고(freeze), 마지막 판단 부분만 내 문제에 맞게 학습 → 파인튜닝(전이학습).

무엇이 전이되나 — 층의 역할 차이

[앞쪽 층] 선·모서리·색   ← 보편적! → 물려받음 (freeze)
[중간 층] 질감·무늬
[뒤쪽 층] 눈·귀·형태     ← 구체적 → 새로 배움
[판단]   개 / 고양이
데이터가 적을 때 사전학습 쪽이 크게 앞서요. 사전학습된 특징을 재사용하니까요.
6

왜 내 노트북으론 벅찰까

원인: 파라미터 개수가 하늘과 땅 차이

학습파라미터어디서
카페 선형모델2개노트북에서 즉시
MNIST 분류기수만~수십만노트북 CPU 몇 분
ResNet18 파인튜닝약 1,100만GPU 권장
대형 언어모델수십억~수천억GPU 수백~수천 대

CPU vs GPU

CPU: 큰 코어 몇 개    → 복잡한 일을 순서대로
GPU: 작은 코어 수천 개 → 단순 계산을 한꺼번에 (병렬)

학습은 방대한 행렬 곱셈이고, 그 안의 곱셈들이 서로 독립적이라 순서 없이 한꺼번에 가능 → GPU에 딱 맞아요 (CPU보다 수십~수백 배 빠름).

😲 LLM의 수천억 파라미터를 1초에 하나씩 세도 수천 년. 그래서 실무는 대부분 직접 훈련 대신 파인튜닝하거나 API 호출.
